Aula 1

Fundamentos — processos, threads e sistemas distribuídos

13 termos
Processo

Programa em execução, memória própria.

Thread

Fluxo de execução dentro de um processo; compartilha memória com as outras threads dele.

Concorrência

Progresso sobreposto no tempo. Não exige simultaneidade real.

Paralelismo

Execução realmente ao mesmo tempo, em múltiplos núcleos/processadores.

Memória compartilhada

Comunicação via mesmo espaço de memória — só entre threads do mesmo processo.

Troca de mensagens

Comunicação por envio/recebimento explícito. Única forma entre máquinas diferentes.

Sistema distribuído

Máquinas independentes, comunicam-se só por mensagens, parecem um sistema único.

Sem memória global

Cada máquina só enxerga sua própria memória.

Sem relógio global

Não existe um tempo único compartilhado entre as máquinas.

Falha parcial

Uma parte do sistema falha, o resto continua rodando — o outro lado nem sempre sabe.

Heterogeneidade

Hardware, SO e linguagens diferentes coexistindo no mesmo sistema.

Escalabilidade

Crescer (mais usuários/nós) sem degradar o sistema.

Transparência

Esconder do usuário que o sistema é distribuído (de localização, de falha, de acesso...).

Aula 2

Arquiteturas e sockets

14 termos
Cliente-servidor

Cliente pede, servidor responde. Arquitetura mais básica.

Multi-tier

Camadas separadas: apresentação, lógica de negócio, dados.

P2P

Todo nó é cliente e servidor ao mesmo tempo, sem servidor central fixo.

Servidor iterativo

Atende um cliente de cada vez, em sequência.

Servidor concorrente

Atende vários clientes ao mesmo tempo (thread/processo por conexão).

Síncrono

Quem envia espera a resposta antes de continuar.

Assíncrono

Quem envia não espera — segue em frente e trata a resposta depois.

Bloqueante

A chamada trava a thread/execução até terminar.

IP

Endereço da máquina na rede.

Porta

Identifica o processo/serviço específico dentro da máquina.

Socket

Par IP + porta; ponto de comunicação de uma aplicação.

TCP

Orientado a conexão, confiável, ordenado — mas mais lento.

UDP

Sem conexão, não confiável, sem ordem garantida — mais rápido.

Delimitação de mensagem

TCP é um fluxo contínuo de bytes — a aplicação precisa definir onde uma mensagem começa/termina.

Aula 3

RPC e Java RMI

14 termos
RPC

Chamada a um serviço remoto que parece uma chamada de função local.

Stub

Representante local (proxy) do serviço remoto, do lado do cliente.

Skeleton

Do lado do servidor: desempacota a chamada e aciona o método real.

Marshalling

Empacotar método + parâmetros + metadados numa mensagem.

Serialização

Converter um objeto no seu estado em bytes.

Passagem por valor

Objeto Serializable é copiado — mudanças no destino não afetam o original.

Passagem por referência remota

Objeto Remote; o cliente recebe um stub que aponta pro objeto real.

RMI Registry

Diretório nome → referência remota. Servidor faz bind, cliente faz lookup.

RemoteException

Toda chamada remota pode lançar — a rede pode falhar de jeitos que não existem localmente.

At-most-once

A operação executa, no máximo, uma vez.

At-least-once

A operação pode executar mais de uma vez (reenvio).

Maybe

Nenhuma garantia — pode não executar, executar uma vez ou mais.

Idempotência

Repetir a operação leva ao mesmo estado final.

Granularidade

Chamadas remotas devem ser poucas e "gordas", não muitas e "finas" — cada uma tem custo de rede.

Aula 4

Web, REST e microsserviços

15 termos
HTTP

Protocolo requisição/resposta em texto — base da web.

GET

Ler um recurso. Idempotente.

POST

Criar um recurso novo. Não idempotente.

PUT

Substituir/atualizar por completo. Idempotente.

DELETE

Remover. Idempotente (repetir dá o mesmo estado final).

2xx / 4xx / 5xx

Sucesso / erro do cliente / erro do servidor. Ex: 200, 201, 400, 404, 500.

REST

Recursos + verbos HTTP + JSON, fracamente acoplado.

Stateless

Servidor não guarda a conversa entre requisições — cada uma carrega o que precisa.

URI bem-feita

Substantivo no plural (/produtos), sem verbo (nada de /getProdutos).

gRPC

Contrato explícito (.proto), tipado, rápido — parecido com RMI.

REST × RPC

REST é desacoplado e interoperável; RPC/gRPC é mais acoplado ao contrato, porém mais rápido/tipado.

Microsserviços

Sistema dividido em serviços pequenos e independentes.

API Gateway

Porta única de entrada: roteamento, autenticação, rate limiting.

Container / Docker

Empacota o serviço com suas dependências — portátil e isolado.

201 Created

Vem com header Location apontando pro recurso novo.

Aula 5

Comunicação orientada a mensagens

15 termos
Direta

Sem intermediário — os dois lados precisam estar disponíveis ao mesmo tempo.

Indireta

Via fila/broker — desacopla tempo, espaço e sincronismo.

Broker

Recebe → armazena → roteia → entrega → monitora.

Work queue

Cada mensagem é processada por só 1 consumidor — escala horizontal.

Publish/subscribe

Um evento pode chegar a múltiplos assinantes/filas.

Exchange fanout

Manda para todas as filas vinculadas (típico de pub/sub).

Exchange direct

Roteia por chave exata (típico de work queue).

Exchange topic

Roteia por padrão de chave.

ACK

Confirmação de que a mensagem foi processada com sucesso.

autoAck=true

Risco: confirma antes de processar — pode perder mensagem se falhar.

Redelivered

Mensagem volta pra fila se o consumidor falhar antes do ACK.

Idempotência (mensageria)

Consumidor não pode duplicar efeito ao receber a mesma mensagem de novo.

Stream / log

Registro append-only; permite reler o histórico (replay).

Comando

Expressa uma intenção, pode falhar, tem destinatário. Ex: ReservarEstoque.

Evento

Expressa um fato já ocorrido, não "falha", vários podem reagir. Ex: PedidoCriado.

Aula 6

Nomeação, localização e descoberta

16 termos
Nome

Como nos referimos à entidade (ex.: pedido-service).

Identificador

Único e estável, distingue a entidade (ex.: UUID).

Endereço

Onde a entidade está agora (ex.: 10.0.0.17:8080).

Binding

Associação nome → endereço/referência. Pode mudar sem mudar o nome.

Domínio

Parte lógica da árvore DNS (um nó + descendentes).

Zona

Unidade administrativa publicada por servidores autoritativos.

Delegação (NS)

Aponta quem é autoritativo por uma subzona — permite administração distribuída.

Resolução recursiva

Cliente → resolvedor: "descubra a resposta final para mim".

Resolução iterativa

Resolvedor → raiz → TLD → autoritativo: cada um responde "consulte o próximo".

Cache / TTL

Por quanto tempo uma resposta pode ser reaproveitada. Trade-off: TTL alto = menos consultas, mudança demora mais.

Registro A / CNAME / MX

A: nome→IPv4. CNAME: nome→outro nome. MX: nome→servidor de e-mail.

Service registry

Nome lógico → conjunto de instâncias + metadados/saúde.

Health check / lease

Teste ativo do endpoint / registro expira se não for renovado (heartbeat).

Client-side discovery

O próprio cliente escolhe a instância, a partir da lista do registry.

Server-side discovery

Um proxy/load balancer escolhe a instância — cliente nem sabe que há escolha.

DHT (Chord)

Localiza sem diretório central: hash(chave) → nó responsável.

Simulado

Temas do simulado que ainda vale revisar

6 termos
8 falácias da computação distribuída

Suposições erradas e comuns: rede é confiável, latência é zero, banda é infinita, rede é segura, topologia não muda, há um administrador só, custo de transporte é zero, a rede é homogênea.

Rede não é confiável

Pacotes se perdem, chegam fora de ordem ou duplicados — é preciso tratar isso na aplicação.

Latência ≠ zero

Toda chamada remota tem custo de tempo, mesmo em redes rápidas — impacta design de granularidade.

Banda não é infinita

Transferir muitos dados tem custo real — payloads grandes/frequentes competem por banda.

Rede não é segura

É preciso autenticação, autorização e criptografia — nada disso é automático.

Topologia muda

Máquinas saem, entram, mudam de endereço — por isso nomeação/descoberta (Aula 6) importa tanto.

Essas "8 falácias" apareceram no simulado de uma turma anterior mesmo sem estarem nos slides — vale a pena conhecer os nomes, é um tema clássico da disciplina.
